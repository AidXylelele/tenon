# form-fields

What the editor's forms show of the language server's `workflow/stepForm` and `workflow/workflowForm`, in the design's words, and the `workflow/edit` actions their changes send. Logic of the workflow editor module, without JSX: its `step-form` renders what it returns.

Owner: web — editor. Decisions: research D2 (short forms, progressive disclosure), D13 (set data keeps incoming data), D14 (a script's result), D15 (schedules), D16 (secrets only in credential fields) of the console redesign (005); information architecture §3 ("If this step fails", "After this step") and §14; design system §6–7; the approved mockups `formHttp`, `formSwitch`, `formGeneric`, `formScript`, `formStart` and `failBox`; the language server's `lsp-extensions.md` ("Step form", "Workflow form", "Edit").

## API

- `formKindOf(kind, fields)`: the form a step takes — the call (`http`, `openapi`, `grpc`, `asyncapi`, `mcp`, `a2a`, else `function`), the run (`script`, `shell`, `container`, `workflow`, by the member written; `script` when none is), or the step's own kind.
- `layoutOf(fields, step)`: `essentials` (every field with an `essentialRank`, from inside its groups, in rank order), `more` (the other settings, the time limit, then `if` and `then`; fields whose words are `hidden`, such as notes and an HTTP call's redirects, are left out; a group that holds essentials gives only the rest of its members, without its own unwritten alternatives such as another kind of run, unless the design names them; a choice whose only value is written is left out), `data` and `failure` (their sections). `pathOf(field, base)`: the field's place below a step or the workflow, `with/endpoint`. `summaryOf(fields, kind, base, unwritten)`: what a closed disclosure holds — named values by count ("No headers", "Headers: 2"), the time limit in seconds ("Time limit 45 s"), the titles of the other written fields — three and "n more", or `unwritten`; one line in sentence case, so only its first part starts with a capital ("No authentication · no headers", "Run only if · time limit").
- `wordsOf(kind, path, field)`: the design's title, help, placeholder, the message for an empty field ("Enter the address to call…"), whether it is mono, the words of its choices, and its control — `data` (takes data from the picker), `seconds` (a time limit), `condition` (the condition builder), `flow` (after this step), `code`, `language`, `httpMethod`, `values` (named values), `cases` (a switch's branches), `hidden` (governed by the step's result), else `value` by its input. Fields the table does not name keep the language server's title. `flowChoicesOf(choices)`: "Continue with the next step", "Leave the block", "End the run", "Go to “Totals”"; `CONTINUE`, the usual way on. `resultText(result)`: the words of a step's result.
- Field edits: `textEditsOf` (an emptied required field keeps its key as `""`, an optional one is cleared), `valueEditsOf`, `clearEditsOf`, `numberCommitOf` and `jsonCommitOf` (a `Commit`: the edits, or a refusal with its reason; an expression in `${ }` is kept as text), `jsonTextOf`, `dataUseOf` (one `useData`, with the step to export).
- Time limit: `timeLimitOf(value)` (the seconds of `after`, `null` when written another way) and `timeLimitCommitOf(field, text)` (a whole number of seconds above 0 as `{ after: { seconds } }`; empty clears it: 30 seconds).
- If this step fails: `FAILURE_CHOICES` (stop, retry then stop, retry then run other steps, continue, run other steps instead); `failureOf(step, form, protection)` reads the choice in force, the retry's settings (retries, seconds, growing; `null` for a policy in another form) and the target — the try that protects the step, else the step; `failureEditsOf(reading, chosen, retry)` and `retryChangeOf(reading, retry)` give the actions in order, each on the text the previous one leaves (a lane after a retry is `setFailure` then `setField …/catch/do`); `retryCommitOf(reading, count, text)` takes a typed count of tries or seconds (a whole number, 0 or more, else refused with its reason; the count in force sends nothing); `failureSummaryOf` and `failureNoteOf` say it in words; `FIRST_RETRY` is 3 retries, 2 s apart, growing.
- `Json`, `JsonObject`, `isObject`: a form field's value.
- How a call sends its data: `SEND_AS_CHOICES` (Message, JSON, Form fields), `sendAsOf(body, headers)` (form fields where a `Content-Type` header says `application/x-www-form-urlencoded`, a message where the body is nothing yet or `{ "text": … }` alone, else JSON) and `sendAsEditsOf(body, headers, chosen)` (`setField` and `clearField` on `with/body` and `with/headers`). `fieldAt(fields, pointer)` finds a field at any depth.
- Named values (a set's values, a script's arguments): `rowsOf`, `memberPointerOf`, `renameCommitOf` (refuses an empty or taken name), `removalOf`, `additionOf` (`value`, `value-2`, … left to fill).
- A switch's branches: `casesOf` (a case without `when` is Otherwise; `null` for anything else), `whenPointerOf`, `thenEditsOf`, `otherwiseEditsOf` (writes an Otherwise case when none is and it does not continue), `caseAdditionOf` (`branch-n` before Otherwise, its condition to fill), `caseMoveOf`, `caseRemovalOf`.
- How it starts: `startOf(schedule, webhookTypes)` — by hand, on a schedule (a cron, or a repeat by duration with its field), by a webhook (an event of one of the webhooks' types) or by an event; `startEditsOf`, `cronEditsOf`, `eventEditsOf` replace the whole schedule.

## Waiting for the language server

Ticket LS S10: the retry's settings in `StepFormResult`, `setFailure handle` with a retry, a retry's "when", and a linear backoff. Until it lands, the retry policy is read and written here (`policyOf`, `secondsOf`, `growingOf`, moved out in M5); a policy in another form (a delay written as `PT2S`, a linear backoff) is said to be written in another form, never dropped.
